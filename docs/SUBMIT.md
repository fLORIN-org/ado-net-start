# Как сдавать работы

Пошаговая инструкция с картинками — на сайте курса:
[работа с репозиторием](https://algorthimization-course-vvodnoe.vercel.app/dup02-vvedenie-v-python/repozitoriy/index.html). Она написана для курса Python, где репозиторий называется
`python-start`; у вас он называется `ado-net-start`, остальные шаги те же. Здесь — правила,
которые проверяет преподаватель.

## Куда класть работу

| Работа | Папка | Пример пути |
|---|---|---|
| практическая работа на паре | `practice/NN-<тема>/` | `practice/02-parameters/SearchApp/Program.cs` |
| отчёт практической работы | та же папка | `practice/02-parameters/report.md` |
| домашнее задание | `homework/NN-<тема>/` | `homework/00-first-project/HelloApp/Program.cs` |
| отчёт домашнего задания | та же папка | `homework/00-first-project/report.md` |
| тест | `exams/quiz-NN-…/README.md` | код результата в таблице |
| контрольная работа | `exams/exam-NN/` | `exams/exam-01/Program.cs` |

Условия заданий практической работы лежат в её папке в файле `tasks.md`.
Заготовки практических работ уже лежат в папках `practice/`: проект открывается и дописывается
на месте, копировать его никуда не нужно. Имя папки для новой работы берётся из таблицы
в `practice/README.md` и `homework/README.md`: преподаватель дописывает туда строку, когда выдаёт работу.

## Имена папок и файлов

| Что называем | Правило | Правильно | Неправильно |
|---|---|---|---|
| папка работы | номер двумя цифрами, слова английские, маленькие буквы через `-` | `01-first-query` | `01 Первый запрос`, `1-query` |
| папка проекта и файл `.csproj` | слова с большой буквы слитно (PascalCase) | `OrdersApp/OrdersApp.csproj` | `orders_app`, `Проект1` |
| файл кода `.cs` | имя класса, который в нём записан | `OrderRepository.cs` | `class1.cs`, `new.cs` |
| отчёт | `report.md` в папке работы | `practice/01-first-query/report.md` | `lesson01_Иванов.md` |
| любое имя | латиница, цифры, `-` и `_`, без пробелов | `02-parameters` | `02 parameters` |

Имя проекта становится пространством имён C#, поэтому в нём нет пробелов, дефисов и русских букв.

## Что не загружается

Папки `bin/` и `obj/` создаёт команда `dotnet build` или `dotnet run`. В них собранная программа
и служебные файлы, они пересоздаются на любом компьютере. Файл `.gitignore` в корне репозитория
уже исключает их из коммитов. Если в панели Source Control видны файлы из `bin/` или `obj/`,
значит, `.gitignore` удалён или изменён: верните его через обновление материалов.

## Сообщение коммита

Первое слово — папка, затем номер работы и что сделано:

| Работа | Сообщение |
|---|---|
| практическая работа 1 | `practice 01: новые заказы с именем клиента` |
| исправление в ней | `practice 01: счётчик строк после цикла` |
| практическая работа 2 | `practice 02: поиск через параметр @pattern` |
| домашнее задание 0 | `homework 00: первый проект HelloApp` |
| тест | `quiz 01: код результата` |
| контрольная | `exam 01: вариант 2` |

Сообщения `update`, `fix`, `файлы`, `123` не принимаются: по ним нельзя понять, что изменилось.

## Перед отправкой

1. База запущена (`docker compose up -d` в корне), программа запускается командой `dotnet run`
   из папки проекта, вывод совпадает с заданием.
2. Отчёт со страницы занятия сохранён как `report.md` в папке работы.
3. Файлы лежат в нужной папке, имена по правилам выше, `bin/` и `obj/` в коммит не попали.
4. Если для решения использовался ИИ, в начале файла `Program.cs` есть комментарий: что спросили и что взято из ответа.
5. Работа ушла на GitHub: на странице репозитория виден ваш коммит.

Все работы загружаются в ветку `main`. Отдельные ветки и Pull Request для заданий не создаются.
