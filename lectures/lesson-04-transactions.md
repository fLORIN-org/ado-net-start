# Занятие 4. Транзакции и откат операций

Страница занятия: [Транзакции и откат операций](https://algorthimization-course-vvodnoe.vercel.app/mdk0111-ado-net/lessons/04-tranzakcii/index.html)  
Практическая работа: [`practice/04-orders`](../practice/04-orders/README.md)

## Что изучили

1. Без транзакции каждая команда сохраняется сразу, и сбой посередине оставляет в базе часть операции.
2. Транзакция объединяет команды: `BeginTransactionAsync`, команды, `CommitAsync`. Изменения сохраняются все вместе или не сохраняется ни одно.
3. Откат — `RollbackAsync` или закрытие транзакции без `CommitAsync`. После ошибки сервер отклоняет команды транзакции с кодом 25P02, а `COMMIT` превращает в откат без исключения.
4. До `COMMIT` изменения видны только в своём соединении. Номера, выданные в отменённой транзакции, не возвращаются.
5. Точка сохранения отменяет часть транзакции: `SaveAsync`, `RollbackAsync(имя)`, `ReleaseAsync`.

## Термины

| Термин | Значение |
|---|---|
| транзакция | группа команд, которую база выполняет как одно целое: `BEGIN` … `COMMIT` или `ROLLBACK` |
| `COMMIT` | сохранение всех изменений транзакции |
| `ROLLBACK` | отмена всех изменений транзакции |
| `READ COMMITTED` | режим изоляции PostgreSQL по умолчанию: команда читает только сохранённые данные и изменения своей транзакции |
| точка сохранения | `SAVEPOINT`: отметка внутри транзакции, к которой можно откатиться, не отменяя всю транзакцию |

## Пример: заказ в транзакции

```csharp
await using var connection = await dataSource.OpenConnectionAsync();
await using var transaction = await connection.BeginTransactionAsync();
try
{
    // INSERT в orders, затем для каждой позиции INSERT в order_items и UPDATE products
    await transaction.CommitAsync();
    return "оформлен";
}
catch (PostgresException e) when (e.SqlState == PostgresErrorCodes.CheckViolation)
{
    await transaction.RollbackAsync();
    return "не оформлен, на складе не хватает товара";
}
```

## Частые ошибки

| Что произошло | Почему | Как правильно |
|---|---|---|
| программа пишет «не оформлен», а строка заказа в базе есть | команды выполнены без транзакции | открыть транзакцию до первой команды |
| `25P02: current transaction is aborted, commands ignored until end of transaction block` | после ошибки в транзакции выполнена следующая команда | откатить транзакцию или вернуться к точке сохранения |
| `CommitAsync` прошёл без ошибки, а данных в базе нет | транзакция была в состоянии ошибки, сервер выполнил откат | не проглатывать ошибку внутри транзакции |
| все команды прошли, а данных в базе нет | не вызван `CommitAsync`, транзакция откатилась при закрытии | вызвать `CommitAsync` в конце блока `try` |
| в номерах заказов пропуск | номер был выдан вставке в отменённой транзакции | исправлять ничего не нужно: счётчик номеров не откатывается |
